# 项目接入：只核当前动作需要的基线

先读使用项目的任务书、状态入口和本轮交接，复用已有指针。项目已有资料时直接定向读取，不让PM重填一套表，不全量搜索其他仓库。

## 定位产品与工作边界

明确这轮要演示的用户任务、本期范围、当前状态及其唯一记录位置，以及允许修改的文件/工程。产品规则以PRD或该项目明确的产品定义为准；原型、代码、会议建议与已确认要求分别标来源。遇到承重规则冲突先提出取舍，不为做出完整界面自行补规则。

PRD共写与原型实现是不同任务；需要修改产品定义时交回其负责人，或在已有授权内先更新定义。无需为了使用本skill额外安装其他skill。

## 设计与演示基线

从当前页面和项目入口确认生效DS的版本、组件/token及源码仓操作指南。沿用已认可的布局、交互与公司规范；包内说明页规则只定义信息呈现的共通要求，具体视觉以使用项目的DS为准。不要把历史DS指南或未装载的资源认作实际生效版本。

### 首次setup或更新DS时

本包不依赖特定公司的仓库、维护者或专线session。先从使用项目已有入口找到DS；没有可用指针时，只向使用者确认权威入口或负责人，不要求其整理整套资料。AI取得读取授权和必要账户权限后，负责定位、获取、核对并接入。

把以下信息补到项目已有入口或DS记录中；没有合适位置时可用一份`ds-context.md`，不复制进插件安装目录，不另建重复状态表：

| 记录项 | 足够继续工作的内容 |
|---|---|
| 权威来源与导读 | 仓库/文档地址、维护方指定的Agent导读路径；多个DS时写明本产品适用哪个 |
| 推荐版本入口 | 维护方指定的release/tag或分支；“最新推荐”不默认等于默认分支或最近提交 |
| 消费方式与资源 | 对现有工程使用组件依赖还是独立原型包；包/构建说明入口、运行依赖、组件API与使用政策、样式和tokens的位置 |
| 本轮固定身份 | 解析后的源提交、包版本与摘要、对应关系及核查时点；仅本机可用时标本地快照 |
| 接入结果与维护方 | 实际加载位置、最小试用结果及未验边界；更新问题交谁处理，未指定时如实留待确认 |

**获取。** 对Codeup等私有仓，使用成员自己的已授权连接器或Git身份，不随包携带凭据。连接器可先解析仓库及推荐ref，再按解析出的同一提交读导读和所需文件；需要整套资源时，按发布入口下载，或将指定提交取到独立缓存/检出目录。已有工作树先核本地改动，不用拉取更新覆盖业务写区。没有连接器时可用已认证Git；两者都不可用才请人完成登录/提供已批准的离线包，私有代码不转投其他外部服务。

**选择消费包。** 优先维护方提供的、适配当前工程的已发布包；包应能定位来源并带必需的组件、样式、资源及使用说明。只有源码时，先读构建说明，确认依赖、命令和允许执行范围后再构建；不将clone成功或本机生成目录称为已发布包。下载不等于运行授权，按实际任务权限决定安装依赖、构建或启动。缺构建链或必要资源时把具体缺口交维护方，不让PM猜技术字段。

**固定并接入。** 开始一轮新工作或明确要求更新时查询推荐版本，将浮动入口解析为固定提交/包身份；文档、组件和样式应来自兼容的同一发布基线。核包的来源对应与摘要，按导读接入现有工程，用本轮代表组件确认API、样式及实际资源加载，并做必要的界面检查。拿不到校验依据时标未核，不自造“已验证”。只读到了规范，不能报告已接入真实DS。

**后续更新。** 记录新版与本轮固定版的差异，按影响选择升级时点；不在进行中的共创/验收里静默换包，不因检测到新提交重开整套流程。断网可继续使用已核缓存，但说明最新性未确认；升级失败可恢复上一版依赖/资源及引用记录，保留业务改动。说明页规则随插件更新，公司的组件与使用政策随项目DS更新，两者不互相冒充。

### 尚无DS，或需要专线维护

若DS或页面基线尚不可获得，可推进已授权的内容/交互草图并标待核，不宣称完成品牌或组件对齐。不因缺DS自行创造一套公司视觉规范。

单个项目接入由当前agent完成即可。多条产品线反复遇到版本漂移、发布缺件、使用政策冲突，或确需持续建设DS时，建议指定维护人；使用者愿意时，可创建一条DS专线session。专线是可选的工作组织方式，不是插件依赖；只有人明确要求创建才执行，否则给一段自足任务说明。

这段说明应交代现有仓库/设计材料、目标消费形态与允许写区；目标是核清权威源、补Agent导读和可复现消费包、建立版本及升级说明，并用一个代表页面验证。权限不足或来源有争议先报告缺口；未经授权不发布、不改业务工程。验收以另一使用者能按导读取到固定版本并接入为准。专线结论落在团队可访问的仓库/文档，产品agent靠这些入口消费，不靠私有聊天记忆或特定session编号。

演示控制与业务操作分开，控制只补正常操作难以构造且需要说明的起始条件、响应或异常；未接后端可模拟响应，但后续仍走产品校验和反馈。说明以实际可见范围和本轮判断需要为准：通用身份不用到处重复，混有真实/模拟、独立分享结果或离开原说明范围时，要保留必要的来源说明。具体样式引用项目演示规范。

## 执行与核验

依据已有工程的生成链、启动/构建方式和写区操作，不默认新建工程、覆盖他人工作或重启共享服务。只核本轮变化和受影响行为；源码检查、实际界面走查、PM确认、真实服务验证各自说明对象和范围。

交付阶段沿用已约定的产物及渠道。无需独立HTML、源码归档或远端发布的任务，不为套流程创造这些交付物；确有这些产物时，固定版本并核实际接收副本，细节证据保留指针即可。
