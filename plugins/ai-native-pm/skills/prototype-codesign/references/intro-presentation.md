# 原型说明页呈现

说明页回答“当前看什么、从哪进入、以哪份为准”，是评审入口，不是产品业务页或第二份状态台账。流程含义与转移只引用[原型共创状态流](workflow.md)；产品线主控在一个既有状态源记录实例当前值及依据，本页从其派生，保留该源指针和本次生成时点。状态有变化时重新派生；不手写另一套状态，不在封面增加独立切换状态的控件。

### 信息顺序与按状态裁剪

首屏按“原型名及本轮目的 → 当前关注点/短走查路径 → 进入原型”组织。当前状态沿用实例源的原值，以普通文字或中性标签呈现；不要套用业务成功/失败配色。来源、版本和证据按下表补充，详细清单折叠或链接出去。没有取得实例状态依据时不推断已确认或已交付，也不另造第五个流程状态。

下表只规定展示重点，不定义状态含义、转移条件或新的审批门。

| 实例源中的当前状态 | 首屏重点 | 版本与入口 |
|---|---|---|
| 方案对齐中 | 本轮讨论范围、关键动线和待决策问题。 | 给能开始讨论的原型入口及方案依据；不强制填齐交付索引、仓库提交或完整核验清单。 |
| 设计对齐中 | 本版视觉/交互调整、沿用的业务规则和待对齐处。 | 给短验收路径及必要设计依据；不把“已按建议修改”写成设计师已确认。 |
| 待交付 | 当前应核的交付副本、使用方法及尚待完成的交付项。 | 对已有约定产物展示固定身份与实际入口；未就绪项如实标注，不造空链接或把讨论快照标成最终交付。 |
| 已交付 | 本轮交付版本、打开方式及后续反馈入口。 | 展示约定产物的固定版本与必要入口；源码归档、独立HTML等若同时提供，分别标明，不用浮动“最新版”替代固定定位。 |

### 公司DS的使用与边界

- 复用当前有效公司DS的排版、间距、色彩、链接和按钮；“进入原型”是主操作，源码/固定提交/证据是次级链接。版本摘要用可读短标识，完整SHA放详情或链接，不堆进标题。
- 说明页与产品界面分层，不靠插入常驻横条、挤压产品布局来承载评审元信息。根据需要用简短说明区、可收起说明或独立分享时的入口页；不强制每轮新增拦路封面。必要演示控制继续引用[演示层现行规范](project-context.md#design-baseline)。
- PM确认、设计确认与独立核验分别写明对象、版本及范围；“已交付”不等于真实服务验证通过。只在影响本次判断处说明本地模拟、未接服务等具体边界，不恢复逐弹窗通用免责声明。
- 样式和组件不随流程状态另造一套主题，不新增共享token或组件。应用到具体原型时，只验当轮变更：检查入口可用、标题与源状态一致、交付版本能定位，并在实际固定副本上真实渲染。

本节仅维护说明页呈现，不代产品线维护实例状态，不修改各线源码、共享DS产物或发布物。旧“三种用途”及“双维度”讨论保留为历史，不能另立流程分类；实例按流程维护方唯一源消费。本次仅文档约定，尚未代表各线已应用或新说明页已完成视觉验收。
