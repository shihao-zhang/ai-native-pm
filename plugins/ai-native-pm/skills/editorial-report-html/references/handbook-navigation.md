# 导航与阅读深度契约

在多章往返查阅，或读者需要先看全貌、再深入细节时读取。导航解决“去哪里”，阅读深度解决“先理解多少”；二者分开选择，不把静态文档改造成依赖脚本的 Web App。

默认面向电脑宽屏；下文移动端布局与验收仅在用户明确要求或项目已有移动端要求时适用，已有移动端支持保留。

## 1. 先判断是否需要章节导航

章节地图与增强导航在同时满足以下条件时优先使用；整篇速览的启用不受这些条件限制，见第 4 节：

- 多个章节之间存在实际跳转需要，章节数不是门槛；
- 章节可独立查阅，而不只是连续论证；
- 读者会在目录、相关章节和原位置之间往返；
- 页面仍需支持打印、全文搜索和离线阅读。

连续阅读即可完成目标时优先普通锚点导航。是否需要不同阅读深度，另按第 4 节判断，不由章节数量或体裁名称决定。

## 2. 首屏章节地图

章节地图不是第二份摘要。每个入口只保留：

1. 编号或短标签；
2. 章节标题；
3. 一句话说明读完能解决什么问题；
4. 按需添加覆盖范围或前置依赖。

卡片必须使用真实 `<a href="#chapter-id">`。章节顺序代表依赖时明确写出；不存在依赖时不要伪造学习路径。

若手册服务两个以上明确受众，先标出共同必读，再按受众分组角色章节，最后单列方法与附录。角色路径不能只在首屏出现一次，吸顶目录也应保留“共读 / 角色 A / 角色 B / 附录”等分组线索，避免后续退化成无法辨别用途的扁平章节列表。

## 3. 吸顶导航

- 使用真实锚点，不用只有 `data-*` 的按钮冒充链接。
- 当前章节用 `aria-current="location"` 与视觉状态同时表达。
- 保留 URL hash、复制深链、浏览器前进/后退和键盘访问。
- 布局按信息量选择：长标签或章节较多时可用桌面左侧 rail；短标签可用顶部横排。卡片式菜单不是默认答案，不能为了形式占用大块阅读空间。
- 导航高度保持克制。桌面可横排；移动端优先单行横向滚动，或“当前章 + 展开目录”，不要换成占据大块首屏的多行按钮墙。
- 设置 `scroll-padding-top` 与章节 `scroll-margin-top`，避免标题被吸顶栏遮挡。

## 4. 选择阅读深度

- 用户要快速掌握整篇全貌，或长材料兼有扫读与精读需求时，考虑“速览 / 全文”；明确要求模式切换时必须提供切换，不能只做前置概览和跳章链接。速览是整篇的核心认识，不是只显示当前章，也不是机械抽取每章第一段。
- 读者需要排除其他章节干扰、一次读一章时，才考虑逐章专注。不要默认叠加速览、全文、专注三个模式；现有手册骨架默认演示速览 / 全文，不强制其他任务增加模式。
- 短文或连续阅读已足够时，只需核心认识或结论前置，无须增加模式。金字塔组织是内容基础，不依赖开关。

### 整篇速览如何成立

先明确读者看完应能复述或判断什么，再从正文选择支撑它的内容：核心认识、关键关系或依据、会改变判断的条件，以及有用的深读入口。不是每项都要单独成块，也不是把全文缩成标题目录。

速览模式应有独立的整篇阅读体验：把分散在全文的精华按理解关系重新组织，并为此调整页面密度、构图与导航。无需为长文服务的大标题、元数据、目录和章节导语应收起、缩减或重排，让屏幕主要承载精华；仅隐藏后续章节、保留原来的第一章和长文页面布局，不算完成这项转译。这里的“独立”指阅读任务与呈现效果，不要求另建文件、维护第二份事实或采用特定 DOM 结构。

架构、流程、因果、反馈或对比关系能显著降低理解成本时，优先让视觉抽象承担解释，可复用正文图或重新构图。每张图回答一个清楚的问题；对象、流向、反馈和边界与材料一致，不把分类画成流程，不把教学编排冒充系统实现。图旁保留必要读法与来源条件，不紧邻重复整段正文。不规定图数、节点数、卡片数量、配色或版式。

“一屏或接近一屏”是实际桌面视口下的设计目标，不是硬配额。信息密度来自有用关系，不是堆字；不可为塞进一屏缩小关键文字、裁切内容或删掉成立条件，必要时允许继续滚动。关键判断与边界同层可见，细节可下沉。

速览必须可回溯到全文，不能新增未经材料支持的事实或升级确定性。能复用的内容避免重复维护；重新提炼或另画时，建立对应正文的入口，并在正文修改后同步核对速览，不要求特定的克隆或渲染实现。

### 实现与降级

手册模板提供可调整的默认阅读外壳：深度开关固定右上、全文左栏目录，速览时收起目录与长文元数据、扩展精华阅读区。优先复用可运行交互；根据材料调整尺寸、色彩、字体、图数及内部构图，不把样例区域数量或列宽当成要求。短文或零脚本任务仍按上文选择简化方案。

默认全文可读；脚本只提供由读者显式开启的阅读增强。关闭 JavaScript 后全文、内部锚点和浏览器搜索仍可用。零脚本交付使用静态前置概览与正文锚点，按需用原生折叠承载补充内容，不保留无效模式按钮。

- 模式控件使用原生按钮及明确状态（如 `aria-pressed`），名称说明切换的是整篇深度还是当前章节。
- 速览进入具体正文时先恢复全文，再跳转并让键盘焦点可达；正文深链不能落进隐藏区。模式、URL 与前进/后退一致，直接打开和刷新也应得到一致状态。
- 从全文进入速览后，切回可恢复阅读位置；若通过某个深读入口展开，则到该入口对应位置，不强行回到旧位置。
- 逐章专注同样保留真实锚点与退出路径；CSS 仅在脚本增强状态下隐藏章节，不能默认隐藏再靠脚本补正文。
- 打印恢复全文，避免只打印速览或重复打印两份内容。验收时分别检查默认入口、模式入口、正文深链、切换与历史、无脚本及打印，不以静态脚本检查替代实屏验证。

## 5. 章节结构

全文只有一个 `h1`。章节使用 `h2`，章内主题使用 `h3`。推荐节奏：章节编号与用途 → `h2` → 短导语 → 机制或步骤 → 示例 → 关键要点/自检。统一节奏帮助扫读，但不要求每章机械复制相同数量的卡片。

正文中的跨章引用也使用真实锚点。若“来源摘要”和“作者解读”并存，分别标明来源类型与结论状态，避免把批判性笔记伪装成底本原意。

## 6. 验收

- 无 JavaScript：全部主要章节可见，锚点可跳转。
- 通读模式：滚动后吸顶栏稳定，当前章状态更新。
- 多受众：共同章节、角色路径和附录在首屏与目录中的分组一致。
- 速览（若有）：切换后是否形成整篇精华的紧凑视图，而非仅停在全文的概览第一章？不读全文能否理解核心认识与关键边界，关系图有无解释作用？深读入口、切回位置、hash 与历史应一致。实际是否接近一屏须记录视口，不靠裁切达标，开关可用不等于速览体验通过。
- 专注（若有）：只显示当前章而不冒充整篇精华；切章、hash、前进/后退一致。
- 移动端：导航不形成多行按钮墙，正文不被遮挡。
- 打印：导航隐藏、全部章节恢复、章节和关键组件避免错误分页。
