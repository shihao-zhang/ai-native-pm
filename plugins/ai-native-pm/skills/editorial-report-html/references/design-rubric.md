# 编辑型 HTML 设计准则

规划新报告、选择候选 HTML 或做最终对抗检查时读取本文件。

默认面向电脑宽屏。下文移动端布局与验收条款仅在用户明确要求或项目已有移动端要求时适用；保留模板或产物已有的移动端支持。

目录：阅读契约 → 视觉转译 → 源图分流 → 密度 → 证据 → 无障碍 → 自包含 → 反模式 → 视觉 QA。

## 1. 选择阅读契约

| 页面模型 | 读者核心问题 | 首屏必须回答 | 正文常见结构 |
| --- | --- | --- | --- |
| 决策简报 | 应该相信什么、做什么？ | 结论、关键判断、决策语境 | 判断轴、证据、权衡、决策门、开放项 |
| 对比报告 | 选项究竟差在哪里？ | 范围、共同坐标轴、暂定结论 | 对象画像、归一化矩阵、工作流、建议 |
| 长篇手册 | 从哪里开始、具体怎么做？ | 索引、角色路径、起步顺序、章节地图 | 章节、步骤、示例、自检、术语表 |

这些是常用配方，不是穷举。允许多种表达服务同一主要阅读目标，不要求架构解析、事件复盘或论点辨析硬套三类名称。

三种配方均明显不适用时，先给人类一份简短自定义提案：读者要理解或判断什么、主线顺序、核心关系如何表达、哪些内容默认展示或进入深读，以及现有配方为何不适合。确认后再实现页面；确认前可继续读取已授权材料。用户已明确给出这些结构要求时视为已对齐，不重复询问；普通章节调整无需走此出口。自定义仍须满足相同来源、工程与验收底线，不扩展到 Web App。

完成自定义产物后，可在交付中提报“原配方不适用处、采用结构、用户反馈与验证证据”，供人类回流维护会话；没有反馈就注明待比较。不自动跨会话发送、写入技能/记忆或新增永久模板。

## 2. 把内容翻译为视觉形式

以下是可组合的表达建议，按理解任务选择，不按数量强制映射：

- 论证或细微差异：带强主句的短段落。
- 重复字段需精确查阅：可用表格。
- 两面权衡：对位或双栏比较。
- 序列、阶段或状态变化：流程或时间线。
- 分类：可用列表、树或有明确分组作用的卡片。
- 并列对象：可用网格、对位或开放布局，数量与列数按内容密度确定。
- 证据缺口或警示：靠近受影响主张的克制提示框。
- 图可承担关系解释、视觉证据、界面示例或概念理解；交叉引用时编号，需要解释读法、来源或边界时加图注。

视觉几何必须和内容关系一致：闭环必须表现反馈边，阶段必须保持顺序，矩阵必须定义轴，比例图不得暗示材料未支持的总体规模。每张图聚焦一个主要理解任务，由关系决定构图，不强套统一卡片。

图表字段重合不等于认知作用重复。图可表达拓扑、归属、流向或整体模式，表可供逐项核对；两者各有作用时可以共存。删图或缩表前，检查是否丢失上述关系、必要属性或关键条件；仅重复同一呈现任务时合并。正文和图注补充必要读法与条件，不紧邻图再完整复述一遍。源表截图的去重按下一节处理。

拒绝把 Markdown 标题和 bullet 一对一套进边框。如果每节都是“标题 + 一段话 + 矩形框”，页面仍只是换装后的 Markdown。

## 3. 源图分流与去重

输入包含图片目录、`image_inventory` 或批量源图时，先为每张图确定唯一的主要呈现方式：

| 状态 | 使用条件 |
| --- | --- |
| `transcribe` | 表格截图等内容能完整转成语义化 HTML；核对覆盖后不再重复展示原图 |
| `preserve` | 流程图、关系图、架构图、趋势图等由空间关系或视觉编码承载信息 |
| `exclude` | 封面、空白占位、纯装饰图，以及对当前交付无作用的二维码 |
| `dual` | HTML 与原图分别承载不可替代信息；图注必须说明差异 |

“务必嵌图”默认表示图片独有信息不得遗漏，不等于逐图展示；用户明确要求逐图原样呈现时才全部保留。删除或隐藏源图前，逐项确认数字、文字层级、合并关系、分类、颜色语义、优先级和注释已被结构化覆盖。无法无损转写时保留原图，并就近说明尚未结构化的信息。保留的内容图必须有描述信息的替代文本与读图要点。

## 4. 密度与节奏

- 正文字号、行高、行长和章节间距按字体、内容密度和实际视口决定；16–18px、1.6 行高、60–75ch 行长可作为连续正文的起步参考，不是统一门槛。
- 首屏判断数量、卡片数量及列数由信息层级与阅读负担决定；不为配额删去关键条件，也不为凑满布局增加内容。
- 长手册的章节地图卡只承载真正并列的章节入口；每张卡最多说明章节主题、用途、覆盖范围和前置依赖，不把正文摘要重复塞满首屏。
- 元数据使用小字号，但重要判断必须保持正常正文尺寸。
- 宽表可通过宽内容区、拆分维度或重组布局适配；仍需横向滚动时提供可见提示，不能裁掉信息。
- 检查 `h1/h2` 的真实换行；谨慎使用手写 `<br>`，避免把英文短语、数字单位或末尾一两个词甩成孤行。hero 应保留主题、范围或入口所需的空间，不以占满一屏为目标。

留白、边框、阴影、色彩可服务分组、主题识别、氛围与阅读节奏。允许克制的审美表达；编码事实时保持一致，不以颜色、面积或位置暗示不成立的关系，不妨碍阅读。

降低阅读门槛不等于降低内容深度。压缩前保留读者所需的事实、核心洞察与因果链；纠正材料中过强的结论时，保留仍成立的分析问题。核心洞察、支撑主线的关系图及可能改变判断的条件默认可见；完整矩阵、机制细节、案例与证据可按需展开，`summary` 应说明实质判断或阅读收益。按认知作用分层，不把重要结论藏起来，也不为保留所有素材而平铺；字数、图数或表格行数减少均不单独证明信噪比提高。

## 5. 可信度与证据边界

把两个维度分开：

- **来源类型**：一手材料 / 独立复核或同行评审 / 二手转述。
- **结论状态**：确认 / 推断 / 类比 / 待验证。

一手来源不天然比独立复核更可靠；标签只说明来源位置和作者当前判断。把标签放在关键主张附近，提供可用的来源链接和变化事实的数据截止日期。不得把来源中的保留语气升级成高管摘要里的确定结论。

## 6. 语义与无障碍基线

- 只保留一个 `h1`，章节名使用真实 `h2`。
- 按角色使用 `header`、`nav`、`main`、`section`、`aside`、`footer`。
- 提供 skip link、可聚焦的正文目标和清晰的键盘焦点。
- 有信息的 SVG 设置 `role="img"` 与可访问名称；装饰性 SVG 对辅助技术隐藏。
- 可选深度优先使用原生 `details/summary`。
- 正文要求读者打分、勾选、标记或选择时，提供原生 `input`，或明确可打印的 `□` / 空白记录位；若后者在屏幕上不可交互，就近写明“打印后填写、网页版不保存状态”。不需要保存状态时不要伪装成依赖脚本的应用。
- 颜色不得是唯一信号；普通小字号文字与背景对比度至少达到 4.5:1。
- 尊重 reduced motion；打印时隐藏无用导航并避免组件被随意拆页。
- 长表打印时允许表格跨页，重复 `thead`，并尽量避免单行被拆开；禁止对可能超过一页的整张表或其 wrapper 强制 `break-inside: avoid`。
- 打印后仍需追溯的关键来源必须保留入口：在来源说明、来源索引或附录来源列追加 URL 或稳定来源编号，不要求把每个正文超链接都展开成长网址。

## 7. 自包含工程基线

所有风格共同使用自包含单文件、内联 CSS、系统字体和内联 SVG；禁止运行时外部资源。普通来源超链接不属于运行时依赖；远程图片、字体、样式、脚本、iframe 和媒体属于依赖。

默认只按阅读需要加入离线安全的内联渐进增强，关闭 JavaScript 后正文与锚点仍须可用。用户或交付环境明确要求零脚本时，移除全部脚本及脚本专用控件，用原生 HTML 保留阅读功能；该选择与外观无关。

## 8. 反模式

发现以下情况就修改：

- 叙事报告被做成监控仪表盘。
- 每个 bullet 都升级成卡片。
- 用 11–12px 正文塞入更多内容。
- 中文散文大面积使用等宽字体。
- 视觉效果压过内容、降低辨识度，或让普通数字显得具有未经支持的重要性。
- 多个 verdict 提示框重复同一判断。
- 图既不帮助理解、提供证据，也不服务主题与阅读节奏。
- 把闭环画成没有回边的单向步骤，或用比例图暗示材料没有支持的总体规模。
- 完整 HTML 表格旁重复展示同内容的原始表格截图。
- 要求读者打分、勾选或选择，却没有控件或可打印记录位。
- 只有 hover 才能看到含义。
- hero 占满一屏却没有结论、范围或入口。
- 来源列表与所支持的主张分离。
- 移动端只缩小桌面图，导致无法阅读。
- 用无锚点按钮切章，导致章节无法深链、浏览器历史失效，或关闭 JavaScript 后主要章节消失。
- 为达到 FAQ 数量预算制造显而易见的问题。

## 9. 视觉 QA

默认检查桌面宽屏；移动宽度仅按上述适用范围检查，并在验收结论中记录实际使用的视口尺寸：

1. 首屏：读者能否说清主题、阅读契约、时效性和下一入口？标题是否出现孤词、异常断行或被 hero 过度挤压？
2. 导航：锚点是否正确落位并有清晰焦点？长手册滚动后是否能识别当前章，移动端是否仍保持紧凑？
3. 密集中段：表格和图是否无需缩放即可阅读？横向滚动的宽表是否有可见提示，视觉几何是否忠实表达关系？
4. 源图：保留的图是否提供正文或 HTML 表格没有的关系信息，省略的图是否已完整覆盖？
5. 操作承诺：打分、勾选、标记、选择是否真的有可操作或可打印的记录入口？
6. 可选深度：details 折叠和展开时是否都能理解？
7. 收尾：页面是否以决策、开放项或下一步结束，而不是消失在来源列表中？
8. 打印：导航、背景、颜色和分页是否处理妥当？长表能否正常跨页并重复表头，关键来源能否继续追溯？
9. 失效条件：若报告包含时效性判断或建议，footer 是否说明什么信号出现就应回炉？

视觉检查结束后再做一次内容复读。漂亮但重复或推理薄弱的页面仍是弱报告。
