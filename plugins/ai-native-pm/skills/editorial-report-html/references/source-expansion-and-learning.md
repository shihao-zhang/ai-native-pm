# 扩展源综合与深度研学合同

来源模式为 `source-expanded` 时读取。深度研学按第 5 节的学习目标与来源任务启用，不依赖页面模型名称。目标是防止把链接索引包装成教材，也防止无边界地阅读全部互联网材料。

## 1. 先确认扩展边界

满足任一信号时识别为 `source-expanded`：

- 用户明确要求研究、更新、核验或跨材料综合；
- 种子材料是论文清单、阅读指南或链接索引，且交付质量依赖链接正文；
- 核心判断缺少种子材料内的证据，用户希望补齐来源。

以下情况保持 `source-closed`：链接只是脚注或延伸阅读；用户已提供完整底本且只要求编辑；用户明确禁止联网或只允许使用给定材料。

识别为 `source-expanded` 不等于已获联网授权。先从种子材料中提取可见 URL 和来源名称，说明拟读取范围、可能新增的事实与耗时，再取得授权。未获授权时停止外部读取，不生成假装精读过的综合结论，也不把任务静默降级成浅包装。

## 2. 建立来源清单

盘点种子材料中的全部候选来源，但只精读完成任务所需的关键来源。每项至少记录：

| 字段 | 取值示例 |
| --- | --- |
| 来源 ID | `SRC-01` |
| 角色 | 必读 / 选读 / 参考 |
| 类型 | 实证论文 / 概念论文 / 官方文档 / 案例 / 二手文章 |
| 状态 | 已读 / 部分读取 / 无法访问 / 超出授权范围 |
| 支持内容 | 所支持的章节、主张或争议 |

优先读取直接支撑核心章节的一手材料、来源间冲突的关键文本，以及影响内部判断的证据。来源数量过大时，盘点全部、分层抽取，不默认逐篇精读；向用户说明关键来源已读数、候选总数、无法访问项和未覆盖的关键缺口，不用单一百分比掩盖遗漏。

## 3. 按来源类型提取

所有来源都提取：核心问题或主张、证据基础、适用边界、局限、与其他来源的关系、对任务的作用。再按类型补充：

- 实证研究：方法、样本或实验、主要结果、统计或测量限制。
- 概念研究：核心命题、机制、论证链、反例和成立条件。
- 官方文档：明确能力、前置条件、版本或时效边界。
- 案例或行业文章：观察、证据基础、选择偏差和可迁移性。

不要强迫非实证材料虚构“实验”，也不要把来源作者的主张自动升级成已确认事实。

## 4. 从摘要升级为综合

多来源任务中，逐篇摘要不能代替跨来源综合；至少回答下列问题。单来源任务则梳理该来源内部的概念、证据与边界，不虚构跨来源共识或冲突。

- 哪些结论形成共识，证据基础是否相同；
- 哪些来源冲突，差异来自定义、方法、样本、时间还是立场；
- 每个结论在什么条件下成立，何时不应迁移；
- 哪些是来源原结论，哪些是跨来源编辑推断，哪些是面向内部工作的启发。

沿用 SKILL.md 的来源类型与“确认 / 推断 / 类比 / 待验证”状态。使用清晰的小节或句式区分“来源说什么”“综合后能判断什么”“对内部工作意味着什么”，不要新增一套密集徽标。

对决策关键、来源冲突、具有时效性或用户明确要求核验的主张做针对性复核；不要求独立核验每个非关键背景句。

## 5. 条件化深度研学

只有同时满足以下条件才启用：

1. 来源模式是 `source-expanded`；
2. 用户目标明确是系统学习、教学、内部教材或能力培养，交付需要概念递进与能力迁移；
3. 任务依赖关键来源的精读、概念综合与学习组织，而非仅解释一个概念或查询操作步骤；来源可以是一份或多份。

启用后，不论使用长篇手册还是自定义阅读契约，材料还必须包含：

- 学习目标、前置知识，以及学完后应获得的判断能力；
- 概念依赖、推荐学习顺序和关键来源的精读提炼；
- 概念框架或证据矩阵；多来源时呈现跨来源关系；
- 常见误区、争议点、适用条件和失效边界；
- 与工作情境相关的静态自测或迁移练习，材料不足时少写，不凑数。

自测使用普通 HTML、表单语义或 `<details>` 展示答案，不得让 JavaScript 成为正文可读性的前提。普通操作手册、知识手册和扩展源报告不因篇幅长而自动加入题目。

## 6. 交付前检查

- 来源清单覆盖了种子材料中的候选来源，并标明无法访问或范围外项。
- 所有决定性主张能回到具体来源、证据或显式推断前提。
- 多来源页面包含共识、冲突与适用条件，不只是逐篇摘要拼接；单来源页面有内部概念与证据综合。
- 未把“已列出链接”写成“已读完来源”，未把“官方来源”写成“已独立验证”。
- 学习型手册满足研学合同；非学习型页面没有被强塞课程组件。
