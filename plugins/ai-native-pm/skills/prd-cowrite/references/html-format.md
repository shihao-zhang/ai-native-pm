# PRD 的 HTML 呈现

确定章节归位、折叠方式或生成 HTML 时读本件。内容起草见 [PRD 模板](../assets/prd-template.md)，阶段与授权见 [共写流程](workflow.md)。已有结构能服务读者时沿用，不因选了 HTML 就整篇重排。

## 1. 四章是推荐骨架

推荐递进是“为什么做、做到哪 → 是什么、怎么运作 → 怎样算完成 → 开工还缺什么”。可以按产品合并、拆分或重命名，覆盖必要问题比凑齐四章重要；从未涉及的主题可以写不适用及理由。

| 位置 | 回答的问题 | 推荐内容 |
|---|---|---|
| 头部 | 我该读什么、以谁为准 | 状态、版本、日期、受众地图、权威范围与上游关系、变更归口、简短变更记录 |
| 背景与目标 | 为什么做、做到哪 | 用户场景、问题基线、目标与指标、本期范围、非目标及再看条件 |
| 产品定义 | 是什么、怎么运作 | 核心对象与关系、必填与可选信息、动线与状态、界面操作、权限、兼容与强约束 |
| 需求与验收 | 每条怎样才算完成 | 稳定编号、需求与定义指向、逐条判定、本期或依赖状态、不可违反的红线 |
| 落地与开放项 | 开工还缺什么 | 接口与依赖、交付节奏、带负责人和触发条件的待拍事项 |
| 按需附录 | 需要补查什么 | 易混术语、旧词对应、带时点的事实快照；重构时才补旧节号映射 |

产品定义通常先说明信息模型，再写动线和界面，最后收规则；中段随实际依赖调整。范围必须在读者理解定义之前可见，可以用独立小节，也可以由目标、非目标和需求状态共同承担。

**定义只维护一处，需求条目引用定义并给判据。** 不再用一个巨大的功能章逐项重复界面、流程与规则。事实快照标明“不是需求”及更新时间，不混进规范定义；已证实的实跑结果也不能为了统一风格降为示意。

## 2. 折叠态就是可读的简版

- 一级尽量对应一个读者问题，二级对应一个主要产物或主题，细节进入折叠。层级服务理解，不把“一节一图”当指标。
- 章、节先给一句结论；结论放在折叠体外，收起后仍能读到。折叠标题说明里面有什么，展开后给依据、条件、边界与必要细节，不另抄一份简版。
- 全收起后，应能讲清做什么、怎样算对、还有什么未定。关键限制或影响当前决策的未知项不能只藏在折叠深处。
- 递进自查只抓“没有后文定义就读不懂当前节”的依赖。当前节本身能读懂、链接仅供深入查看的前向指针可以保留，不机械禁止所有前向引用。
- 图只在所属节出现一次，其余位置跳转引用。必要上下文和图中的结论不能因为去重而消失。
- 从概览下钻到明细时，保留同一分类、名称与层级，回答对应功能的动作和边界；不要展开另一套泛化摘要。是否加点击跳转取决于定位成本。

受众地图按实际读者写，不要求人人通读全文。例如评审人重点看范围、判据与开放项；设计和工程重点看产品定义及相关接口；验收读者重点看逐条判定和边界。面向实现的操作细节不能因评审页折叠而被删去。

## 3. 授权标记与开放项

分批填正文时，图与结论句可以先行，正文只在对应范围已获授权后填入。使用随包构建器时，节内授权标记采用 `<!-- auth -->`；没有标记的节显示待授权，而不把草拟正文当成已获授权内容发布。具体位置和解析方式见 [构建说明](build.md)。

标记只是已有授权的记录，不是授权来源。已有 PM 原话或工作指令已覆盖本节时，直接补齐记录继续，不再为添加标记重新请批。正文获准起草也不表示其中所有建议已拍板，更不代表获准对外发布。

待拍事项统一用 `<mark>…</mark>`，逐项写问题、负责人、触发条件；已拍结论回到其定义或依赖处，离开开放项清单。涉及 agent 要生成的准确字段，未知时在同一处写“未定·不得生成”。不要把所有普通强调都标成待拍项。

构建时核对**源中待拍标记数、页顶待拍数、页面可见项数**，三者不一致就核查遗漏或重复；开放项索引由同一来源派生，不另手写一份数字。计数口径与去重方式以 [构建说明](build.md) 为准，不为追求零待拍而删除仍存在的问题。

## 4. 单源、编号与成品边界

Markdown 是手写内容源，HTML 从源生成。评审在 HTML 上提出的改动先回改源，再重生成；图改其图库，不直接修生成页。构建脚本见 [HTML 生成器](../scripts/build_prd_html.py)，可运行输入见 [正文示例](../assets/example.md) 和 [图库示例](../assets/figures.example.json)。本件不另定义命令参数。

需求与规则的稳定编号写在 Markdown 中，不用 CSS 自动计数承担评审身份。编号一旦被评审或验收引用，不重排、不复用删除条目的号码；需要重构时保留映射。编号形式适配产品，已有稳定编号直接沿用。

正文只呈现当前产品要求、约束和必要依据。作者排产、批次安排、内部审查记录、作废概念的长篇叙述不混入成品。简短变更记录留头部；“删除后是否影响理解现在是什么样”可帮助判断是否应保留。内部评审确需决策依据时可保留可理解的指向，对外版不携带只有内部人员看得懂的编号串。

阅读密度以识别结论和边界为准，不靠遍地加粗；待定高亮保持一致。涉及比例时说明同一比较下的分母。样式和侧栏可以适配载体，不强依赖其他模板或特定设计系统。

## 5. 交付前检查实际页面

先检查生成是否成功、授权范围是否正确、待拍计数是否一致，再打开真实页面核结论与折叠、跳转、图文显示和编号。需要时按目标屏幕检查阅读效果；涉及图时按 [图示指南](diagrams.md) 看实际渲染。

用全收起状态试读，核是否仍能说清本期范围、完成判据与未决问题。结构完整和脚本通过都不能替代可读性验收；本推荐骨架也不预先保证评审效果。

如果约定单文件交付，检查附件、图库及跳转是否在接收副本中可用，不能依赖作者本机相对路径。页头版本与正文同源，避免正文更新而标题或版本摘要仍旧；具体证据口径见[证据与复验](evidence-review.md)。
