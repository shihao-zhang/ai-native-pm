# PRD 图示指南

只在新画、复用或重组图时读相关段。章节呈现见 [HTML 呈现](html-format.md)，填字阶段见 [共写流程](workflow.md)，生成和检查命令见 [构建说明](build.md)。本件把布局经验当可选起点，不把历史返工次数、图数或尺寸当成通用要求。

## 1. 画前先确定要回答什么

每图先说明读者问题、归属章节、分类判据、节点和箭头的含义。规则尚未确定时，不用完整外观掩盖未知；可画讨论草图，但要标明示意与待定，不能让下游按已定要求生成。

图适合表达对象关系、生产流程、用户动线、状态变化和界面区域；验收判据、范围边界、缺口通常用文字或表格更准确。先选信息载体，再决定画不画，不按章节凑图。连续增补使一张图混进对象关系、操作归属和版本变化时，先重定问题，再裁剪或拆分，不固定图数。

两根独立状态轴通常分开表达；若有效组合实际只有一条链，也可以合图。菜单、导航、界面布局图按实际方向和区域关系画，不强套横向流程。

复用上位图或旧图前，逐项核当前术语、关系、状态和裁定。可用的原 SVG 优先复用，适配配色时同步图例；图中的设计示意不自动变成真实字段或产品要求。

### 先选视觉语法与展开粒度

| 读者的认知动作 | 可采用的表达 |
|---|---|
| 比较既有、本次与后续 | 同一分类轴上的平级对照，避免把新增错误嵌入既有范围 |
| 辨认归属 | 容器、分组及归属关系；区分对象与处理步骤 |
| 追踪生成或流转 | 带动作、方向和终点的路径；区分处理依据与直接产物 |
| 定位页面变化 | 简化页面背景，加可识别的节点、浮层、对话或轨迹等必要元素 |

这些是选择依据，不是固定图数或模板。既有内容可退到背景，新增才按理解需要展开；删框删字后仍可能只是平铺文字。布局、嵌套和图例外观同样陈述关系：平级应能看出平级，图例不能伪装成主体节点。颜色随主题和语义确定。

概览中的功能应能在明细找到同名、同层级的动作与边界，不在展开后换成另一套粗分类。跳转仅在定位成本值得时增加，不要求每图可点。分类名若容易误解，补影响理解的工作方式；复杂更名用[术语调整](terminology.md)。

案例：把“已有能力＋新能力”堆成文字框，减少框数后读者仍难辨变化；改为平级范围对照和真实界面元素后，获得本场景PM认可。这支持表达方式的选择，尚未证明跨读者理解率。另有案例中，图上的收音功能在展开后只见“调试”粗表，补成同名动作与边界才接通阅读路径；整体效果仍待评审。业务生成范围后续发生改判，旧图只留作当时表达的例证，不复制其产物数量或连接关系。

## 2. 横向流程图的布局起点

下面只适用于横向主流程或相近状态图；无法服务当前问题时换布局，不为满足画法扭曲内容。

| 元素 | 推荐布局 | 需要人眼核对的地方 |
|---|---|---|
| 主线 | 从左到右，尽量排成一行 | 阅读方向是否清楚，是否被回路切断 |
| 分支 | 放在主线上方，用短连接线表达关系 | 标签是否压线，分支是否被误读为主流程 |
| 回路 | 从下方回接，可用弧线按跨度分层 | 曲线是否穿字、穿框、与别的线混成一条 |
| 线标签 | 放在易对应的线段附近，加与背景相配的垫片 | 垫片是否挡住箭头或其他信息，叠放顺序是否正确 |
| 门禁或确认点 | 作为主流程的一段，箭头止于框边 | 是否绕开门禁，是否穿框，是否暗示未有的自动动作 |

“箭头乱”时先查布局和阅读顺序，再调画工。多条规格同时满足会不可避免地产生交叉时，执行方应指出内容或布局约束冲突，不能悄悄改词、删状态或加概念。

尺寸随展示列宽与内容定。可从正文字号约 13、次要文字约 11、圆角约 8、每行约 12 个汉字、回路分层约 30 像素开始调整；这些只是试排起点，不是验收阈值。最终按实际渲染和缩放后的可读性决定。

为便于移植，优先用简单 SVG 元素和内联属性，避免依赖外部字体或 `foreignObject`。图内 marker 等 ID 带本图前缀，避免多图同页冲突。需要使用检查器不能理解的元素或变换时，保留明确的人眼检查范围。

## 3. 图与字各自承担什么

- **颜色与线型有明确语义**：同一套图保持一致，图例跟图同步；不规定所有产品必须沿用某一套配色。默认图例与本图不一致时调整图例，不能让读者猜。
- **关系由连线表达**：去向、回路、失败出口要在图上看得出；图注补条件和边界，不能用文字替图修补一个指错的箭头。
- **真实与示意分开**：引用概念图时说明哪些只用于示意、哪些已核实。时间戳、成员规则、工具名、自动启动等不能因图里画过就承诺产品已有。
- **改判同步图及图注**：术语、组件、状态或规则改变时，同次检查图例、注记和下游引用；图中旧说法同样会把废弃口径带回产品。

## 4. 检查顺序与工具边界

先检查布局，再运行 [SVG 检查器](../scripts/svg_lint.py)，最后逐张查看实际渲染。自动检查发现问题后先判断并修正，不以命令退出成功冒充图形通过。具体输出、失败条件和支持范围见 [构建说明](build.md)。

几何检查能辅助发现水平或竖直线段穿矩形、文字压线、文字互压、文字横向出界等问题。除非随包版本明确覆盖且实际验证，否则以下内容仍由人眼检查：

- 文字纵向出界、框出界、缩放后的可读性。
- `line`、`polyline`、含斜线的路径、弧线，以及组变换后的实际位置。
- 线与线的交叉、同向重叠、回路横穿主线。
- 标签垫片、背景底带遮挡，以及绘制次序造成的覆盖。
- 箭头大小、方向、可辨认性及导入目标载体后的渲染变化。
- 关系本身是否正确、门禁是否被绕开、实际能力与示意是否混淆。

收到“箭头交错”一类意见，先判断它是否在自动检查覆盖范围内；未覆盖就明确按人眼复查，不能用零告警否定问题。若图被嵌入或转换到别的载体，还要看目标载体中的实际结果。

## 5. 需要分派画图时

工作指令直接写清以下信息，不要求执行方寻找包外流程件：

1. 本图回答什么、落在哪一节、哪些内容已定、哪些仍待核，以及允许修改的范围。
2. 必须保留的节点、术语与状态；每条关系的起点、终点、颜色或线型、标签文字。
3. 状态与关系的依据、版本和真实程度；拿不准处标“未核”，不自行增造。
4. SVG 的载体宽度或 viewBox 约束、渲染验收范围；涉及截图比对时给双方都能设置的实际视口数值。
5. 回报产物位置、viewBox、检查器实际摘要、人工渲染结论及“对内容规格的异议”。验收先读异议，再看几何结果。

若任务只是布局，执行方不改词、不加新概念或未列节点；遇到冲突应回报。内容设计尚未定的任务则先讨论判据，不能用“只负责画图”的指令掩盖定义空缺。

## 6. 图库保持单源

使用随包构建链时，Markdown 放 `{{fig:fN}}` 之类的图位，SVG 内容维护在图库，生成的 HTML 不手改。图库每图包括标题、图注和正文；具体结构及合法图号以 [图库示例](../assets/figures.example.json) 和 [构建说明](build.md) 为准。

可以维护一个总图库，也可以按图分文件后由构建合并。选择后只维护源：按图拆分时不要再手改聚合图库，以免改过图却生成旧页面。工具是否支持及怎样合并，以随包构建说明为准，不另造命令参数。

一张图只在一个章节定义，其余位置引用。遇到“只新增、不覆盖”的既有约束时保留原件，并列生成新版本；不自行清理旧图。维护版式不能替代核对图中的当前产品口径。
